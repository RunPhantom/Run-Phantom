# Native performance lab

Run Phantom can retain bounded native browser timing alongside an application verification report. Capture is disabled by default. In the verification page, select **Include native performance capture in setup**, reconnect the local app with the generated setup, then open a lab window. Exercise the app yourself and capture the readings. The setup uses `performanceEvidence: { enabled: true, metadata: "none" }`.

The optional SDK metadata mode `"origin-path"` permits bounded resource/script locations. It removes credentials, queries and fragments and applies existing credential and exact entered-value redaction. Numeric mode never reads resource URL or script-attribution getters. No mode acquires bodies, server-timing descriptions, DOM attribution, script function names or invoker descriptions.

Each snapshot identifies one SDK document and explicit lab window with native clock facts, seven named observer states, finite numeric values, unknown/positive native loss, malformed records, omissions and overflow. A missing or unfinished measurement is `null`. Measured zero remains zero. The SDK reports the evidence; the daemon validates its closed shape and matching command/window before accepting it. A compromised application can forge SDK reports. This evidence is not independent machine certification.

| Reading | Meaning |
| --- | --- |
| Largest CLS session | Eligible shifts in the selected window, using a one-second gap and five-second session limit. Recent-input shifts are excluded. |
| Qualifying interaction maximum | Largest admitted native Event Timing duration. Native trusted qualifying events use an at-least-16ms future threshold; buffered history differs and browser duration is quantized. This is display only, never INP or all interactions. SDK synthetic clicks are not trusted user Event Timing proof. |
| Long-frame blocking maximum | Maximum blocking duration among admitted native long animation frames, which cover frames of at least 50 ms. Missing frames give `null`, never manufactured zero blocking. |
| Completed resources / transfer size | Resource entries whose native start is in the selected window and which completed before capture. Transfer size can legitimately be zero; it does not imply zero network cost. |
| Paint and navigation timing | Original document readings. LCP is the latest admitted candidate, not a final whole-lifecycle result. Unfinished navigation fields stay `null`. These are display only and do not measure the lab action. |

The optional numeric check accepts only `clsMaxSessionScore`, `longFrameBlockingMaxMs`, `resourceCount` or `resourceTransferBytes`, with `lte`/`gte` and a finite nonnegative limit. Counts and byte limits require safe integers. Units are fixed by the metric. Comparison uses unrounded stored precision. A fresh capture must match an acknowledged begin in the same document/window/connection generation with ordered finite clocks. The relevant observer must be observing with known-zero native loss and no invalid, omitted or overflow evidence. Unknown loss, unsupported APIs and stale/reopened snapshots are inconclusive. The check describes that selected native population, not general performance, causal improvement or business success.

Selected before/after captures compare different windows in the same document with compatible native clocks and fixed units. Differences are descriptive. Review both windows’ coverage; the comparison cannot upgrade incomplete samples or establish causality.

Application processing is capped at 1,000 entries per callback, eight diagnostic resources/frames, at most 32 script inspections per frame and eight retained scripts. One 50,000-unit work budget includes callback/entry/script work and survives begin resets. Location input is bounded before URL parsing, retained parts are bounded, and cumulative retained location allocation is capped. The DTO is at most 16 KiB. Native `getEntries()` necessarily exposes the browser-owned list; Run Phantom cannot bound the browser’s prior native storage or allocation. Native callback drop information may be absent; absence remains unknown. A nonempty `takeRecords()` drain has no drop metadata and therefore cannot establish zero loss. Positive counts remain positive, using maximum reported count rather than adding cumulative reports. Resource-buffer-full makes the resource population incomplete. Teardown/pagehide stops collection; delayed callbacks cannot append stale evidence.

The same existing session command endpoint and MCP `app_act` accept the closed `{type:"performance",phase:"begin"|"capture"}` command. `app_assert` and saved flow predicates use the closed numeric metric shape. Capability `performance-evidence` negotiates protocol 6; prior 1/2/3/4 remain strict and protocol 5 is not implied. Existing coverage, business predicates and quiet requirements retain their behavior. Numeric-only native checks do not claim a network quiet interval.

Reports retain typed optional snapshots in the existing context column. The whole report context stays within 64 KiB; optional native snapshots yield before any existing outcomes, reasons or expectations. All 20 step outcomes remain retained, with explicit omission markers. Reopening validates optional snapshots and preserves evaluated results when stored evidence is invalid or omitted. Restarted/disconnected sessions never reuse a retained snapshot as fresh proof.
