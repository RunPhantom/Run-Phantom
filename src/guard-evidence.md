# Captured guard decisions

The trace span detail shows advisory observations from retained `guard.evaluation` OTLP events. Run Phantom observes producer decisions; it does not evaluate a guard, rewrite captured inputs or outputs, or block a run. `allow`, `warn`, `redact` and `deny` are reported producer actions. An `allow` can follow a fail-open error, so every view keeps execution coverage unknown. The original span status and replay payloads retain their captured values.

The event attributes are `guard.name`, `guard.phase` (`preflight` or `postflight`), `guard.action`, `guard.score` (finite number from 0 through 1), `guard.classification`, `guard.explanation` and `guard.latency_ms` (finite nonnegative number). `guard.error` is an optional explicit boolean. Zero scores, zero latency and false flags remain visible. Missing, duplicated or invalid fields become unknown with explicit field diagnostics. Text is inert, including markup in explanations.

Decisions derive exclusively from the validated `otlp_evidence` source receipt. Cached decisions and decision-like fields in request bodies have no authority. Downloads retain the source receipt; import and subsequent reads rebuild the decision view. Cached span DTOs use a fixed field list and strip derived or extra client fields. Malformed or credential-bearing receipt carriers are withheld from API reads and quarantined as a fixed nonsecret unavailable marker on cache writes. Portable export refuses invalid source evidence rather than presenting it as a successful transfer.

The receipt admits at most 128 events and 256 KiB. The public view displays at most 32 decisions within 32 KiB, with 128-byte guard names, 256-byte classifications and 2,048-byte explanations. UTF-8 boundaries are preserved and display omissions are counted. Exporter drop counts, missing counts and receiver omissions remain independent. Retained receipt indices and producer nanosecond strings are exact; original source indices are unknown when receiver event omissions obscure their positions. These limits do not establish producer coverage.

Receipt capture and validation enforce the built-in credential floor independently of browser redaction exemptions. High-confidence credential shapes, credential assignments and URL credentials are scrubbed before truncation. Complete private-key blocks are removed as one value; ordinary hashes, UUIDs, base64 data, certificates and code remain observable. Cached rereads repeat receipt validation, so an older unsafe carrier cannot become public evidence.

The disclosure rows support keyboard opening and closing and preserve the existing trace-detail layout, brand tokens and responsive shell. Focused tests cover actual JSON and gzipped protobuf ingestion, persisted SQLite content, restart, cache write/read, portable import/export, advisory/error/loss states, numeric zero and privacy controls. Captured local fixture telemetry makes no provider calls.
