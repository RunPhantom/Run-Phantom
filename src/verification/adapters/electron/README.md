# Cooperating Electron windows

This optional adapter is installed by an Electron application's owner. Pass one actual BrowserWindow to `CooperatingElectronSession`; renderer-supplied window IDs, URLs, JavaScript, paths and native desktop targets cannot select authority. The window must use `contextIsolation:true`, `sandbox:true` and `nodeIntegration:false`. Install `installElectronPreload` in its isolated preload with the same host-created authority token. The context bridge exposes only inert capabilities, never `ipcRenderer`, a generic send method, filesystem or terminal access.

Only bounded CSS reads and exact unique-element clicks are supported. Input is **cooperating DOM script**, not trusted native input. A successful dispatch is separate from the declared outcome. `check` uses the existing tri-state verification evaluator. DOM presence can be observed; network/state/signal and quiet absence are unavailable and remain inconclusive. The cooperating application's preload and main process remain part of the trusted computing boundary; IPC identity is not a claim that an arbitrary application is instrumented.

Every response must come from the selected webContents and exact current main frame, with the original document URL, nonce, request and generation. Navigation, renderer loss, timeout or close retires the session. No request is retried. Closing removes only this adapter's listeners and joins its finite capture work; it does not close a host-owned window. The application owner retains responsibility for destroying its own fixture/application window and joining its process.

Capture uses the selected webContents' actual `capturePage` image, with F28 dimensions/byte/retention limits and its existing private artifact store. It always requires explicit raw consent. No pixel masking, privacy-safe screenshot or desktop-wide capture claim is made. The host chooses the private artifact directory; IPC cannot choose a filename. Raw images require human inspection before publication. Metadata reopened from storage does not recreate live Electron authority.

The adapter has no Electron dependency. The cooperating host supplies its existing Electron runtime. Contract tests use controlled interfaces and the real predicate/artifact code; they do not establish real Electron or packaged execution. `bun tests/run-electron-packaged.ts` requires an explicit `RUNPHANTOM_ELECTRON_EXECUTABLE` pointing to an existing macOS Electron.app binary and a private absolute `RUNPHANTOM_ELECTRON_EVIDENCE` directory. It copies the runtime into an owned temporary application, packages the real fixture/preload, requires `app.isPackaged`, captures actual window pixels, observes the terminal process, then removes the temporary profile. Missing runtime is `BLOCKED` with exit2; unsupported packaging is also exit2. Other native platforms and installed runtime resources require their own qualification.

Electron's official [context isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation), [security](https://www.electronjs.org/docs/latest/tutorial/security), [IPC](https://www.electronjs.org/docs/latest/api/ipc-main), and [webContents capture](https://www.electronjs.org/docs/latest/api/web-contents#contentscapturepagerect-opts) contracts informed this boundary. The adapter does not automate unrelated native widgets or attach to user applications.
