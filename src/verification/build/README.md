# Optional React DOM source adapter

Run Phantom can retain a control's source location as SDK-reported context. A location helps a developer find code; it does not establish that code caused a verified outcome.

Consumers can explicitly install `runPhantomSourceProvenance({ enabled: true, renderer: "react-dom" })` from `src/verification/build/vite.ts` in their Vite plugin list, before their React JSX plugin. This source helper uses the existing TypeScript compiler. It does not inject the verification SDK, a connection token, or a runtime probe. SDK capture requires its separate `sourceProvenance` opt-in.

In development, the adapter adds `data-runphantom-source="src/Checkout.tsx:12:5"` to eligible React DOM host JSX. Files must be under the configured project root, use `.jsx` or `.tsx`, and be outside dependency and test directories. `include` can further restrict repository-relative paths. A file's first nonempty line can be `// @runphantom-source-ignore` or `/* @runphantom-source-ignore */`. Known alternate-renderer imports are excluded. Component JSX and unsupported intrinsic tags receive no stamp. Original JSX line and column positions remain available through composed development source maps.

Parsing is bounded to 2,097,152 JavaScript string characters per eligible module. Oversized enabled development modules are left unchanged; disabled development remains an exact no-op. An eligible production module above that limit refuses the build with its safe relative filename, including with `enabled: false`, so size exhaustion cannot silently emit reserved metadata. Explicitly excluded files remain outside the adapter contract.

In production, explicitly installing this plugin strips the reserved static JSX attribute in eligible files, including with `enabled: false`. It does not remove attributes supplied through dynamic spreads, arbitrary HTML, excluded files, or another plugin's later output. The helper does not inspect application behavior or remove arbitrary tokens, imports, or business strings. Applications must keep the SDK and its connection values behind their own development gate.

The installed adapter preserves a consumer's requested production source maps and existing single or multiple Rollup output settings. It calls an existing `sourcemapPathTransform` before applying a privacy floor: repository-contained sources use bounded relative paths; external, virtual, or unsafe sources use stable anonymous IDs. It sets `sourcemapExcludeSources: true`, so maps omit original source contents that could still contain stripped stamps or development-only connection values. This deliberately limits production debugging to positions and safe source identifiers. Original source contents and external source paths are unavailable from those maps. The hook affects only builds where this optional adapter is installed; it is not a universal source-map or secret sanitizer.
